# Contributing

Changes should keep the skeleton reusable, objective-first, Claude Code-native, and technology-neutral.

Before submitting:

- run `./scripts/validate-template.sh`
- keep `CLAUDE.md` concise and move procedures into skills
- avoid fixed model IDs, fixed technology stacks, or mandatory reviewer rosters
- preserve applicability-first behavior
- avoid duplicate sources of truth
- update `docs/TEMPLATE_ACCEPTANCE_TEST.md` when behavior changes
- explain migration impact for existing users

Pull requests should state the problem, proposed change, reusable value, risks, and validation performed.
