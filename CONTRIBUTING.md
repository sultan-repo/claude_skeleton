# Contributing

Contributions are welcome.

## Before submitting a change

- Keep the template project-agnostic.
- Do not assume a specific framework, language, cloud provider, or model name.
- Avoid adding instructions that increase context without clear value.
- Prefer reusable guidance over project-specific conventions.
- Keep examples small and easy to understand.

## Pull requests

A pull request should include:

- the problem being solved
- the proposed change
- why the change belongs in the generic template
- any compatibility or migration impact
- updated documentation when behavior changes

## Style

- Use clear Markdown.
- Keep instructions concise.
- Avoid vendor-specific claims unless required for Claude Code compatibility.
- Do not include secrets, personal data, proprietary code, or organization-specific policies.

## Validation

Before submitting:

- verify file paths and links
- check that placeholders are clearly marked
- confirm the calculator example remains understandable
- confirm the template can be copied into an empty repository


## Onboarding simplicity

Keep `PROJECT_BRIEF.md` as the primary user-editable entry point.

Avoid adding required setup placeholders across multiple files. New framework options should remain optional or be generated after repository inspection.
