# Plan Milestone

1. Read the project brief, execution standard, current plan, status, requirements, architecture, decisions, TODOs, deferred actions, and risks.
2. Inspect the relevant implementation and existing behavior.
3. Reconcile the requested milestone with the ultimate objective and pending work.
4. Define the observable milestone outcome, implementation boundary, dependencies, owners or workstreams, and blockers.
5. Define measurable acceptance criteria and exact validation commands or procedures.
6. Identify applicable user, operational, architecture, data, AI, security, privacy, integration, hardware, performance, reliability, deployment, support, and compliance concerns.
7. Determine the review perspectives and evidence needed. Do not preselect a fixed agent roster.
8. Break the milestone into tasks that can be implemented and validated independently.
9. Update `docs/plan.md`, `docs/status.md`, and related authoritative documents.
10. State decisions requiring approval and the next action.

Do not silently implement a material scope or architecture change while planning.
